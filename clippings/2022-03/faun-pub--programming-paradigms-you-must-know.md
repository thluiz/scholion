# Programming paradigms you must know

## Problem-solving techniques every developer must know of

Developers are problem solvers by nature. Whatever the problem be, we’re ready to try our best to solve it. But not necessarily all the developers use the same tool, the same language to solve it. It depends on the kind of problem, most of the time. There is always more than one way to solve a problem. One could have fewer lines of code. One could have less complex steps. One could be more mathematically styled. One could be async. It differs based on the problem and the problem solver. But to identify the right way of solving a problem, one needs to be aware of the available paradigms in the first place.

And this article is intended to give an idea about the various programming paradigms aka the ways to solve problems.

> A paradigm means the way of solving a problem. A common way or pattern of doing something.

And programming paradigm means the typical collection of programming tools and frameworks that solve the problem in a particular way. There have been a lot of programming paradigms ever since. And we’ll take a look at some of the important ones.

## Imperative Programming

Imperative means commanding. So it is literally giving instructions to the machine to do something. We tell the steps to be followed, the states aka the variables to be used and the assignments to be done. The flow is controlled through instructions.

## Procedural programming

This is the first kind of imperative programming you need to know. And this is most probably what we learn for the first time when we begin as a developer. We start by defining the procedures, the steps, and passing instructions to the system to solve the problem at hand. A procedure is not just a function, as it can either or not return values, take inputs, do operations.

source: https://media.giphy.com/media/QTdvQnZ6MoZjyN3shL/giphy.gif

In this paradigm, the order of the instructions matter. And definitely, we depend on mutating outside states to achieve the result. Hence there are obvious side effects to those instructions.

Example: C, C++, Java

## Object-Oriented Programming

This is one of the most famous programming paradigms where we represent our states using objects that represent an entity in our problem. We use classes with properties and methods inside them to hold state information and perform functionalities.

This increases reusability a lot and extending the existing feature is easier. We can also leverage polymorphism, inheritance, abstraction, encapsulation. Using OOP based approach increases the quality of the solution and provides scalability.

Example: C++, Java, Python, Kotlin, etc.

## Declarative Programming

This is another superset of paradigm. In declarative style of problem-solving, we do not go about explaining the steps and the procedures the system needs to follow. It is more of declaring what to do. It is similar to solving theorems, where we make declarations and tell what to do instead of instructing how to do it. It is more inclined towards the mathematical way of solving problems. So the order of execution does not matter.

## Logic Programming

This is highly a mathematically inclined one. It is used mostly for logical problems like puzzles and proving theorem etc.

It is solely based on logic. It uses the facts and rules within a system to make logical conclusions. It is very similar to proving a mathematical statement through the execution of the program.

Example: Prolog

## Functional Programming

This paradigm also has its roots in mathematical intentions. The logic is abstracted using functions and has a greater dependency on the lambda calculus. We build a pipeline of functions that use the data and execute to achieve the result. But as mentioned earlier, the order of execution does not matter and we do not mutate any state. Hence these are PURE functions. It also does not support loops or if-else like control structure.

Example: JavaScript, Haskell, Scala, Java

## Reactive Programming

This is another style of programming that is highly dependent on the parallel processing nature of the framework, where the data flows as streams for ease of processing. This is not highly functional by nature, but doing it in a functional way using a declarative approach has shown better results for this paradigm of solving problems. This is popular due to its nature of non-blocking and asynchronous way of execution. Processing huge data and latency expected systems leverage this paradigm to overcome practical difficulties.

Examples: Reactive Streams, Spring WebFlux

It is never about a particular paradigm. It is always about the problem you’re solving . Sometimes you need to mix multiple approaches. So, it is always better to think from the problem perspective.

Hope you found this article was helpful and gave a brief idea about the multiple programming paradigms, yet this is not the entire list. I encourage you to explore more to learn more about the other paradigms.
