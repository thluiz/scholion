## 1/1

Things that help you build better software.

Write a list of the main entities and concepts in the domain.

This includes objects, processes, and roles.

For each main entity or concept, write a short paragraph explaining its purpose and role in the system.

Create Class Diagrams.

I use class diagrams to show the structure of these entities:

- attributes
- methods
- relationships 

Use Sequence Diagrams for workflows.

These diagrams will illustrate how objects interact with each other in a particular scenario.

Add links to the Code for Details.

Include references or links to the relevant sections of the codebase for those who want to go deep into implementation specifics.

This is just an entry point; you can redirect people to your code, where the implementation details are.

I create all these things not because someone tells me to do them but because:

- Save me time on every decision
- keep the team on the same page
- help onboarding new people (not just developers)

What's your take on this?
