The post lays out a screencasting workflow built around preparation first and narration later. The author tests the code before recording, adjusts the editing setup to keep the screen clear, and then records the screen without audio.

## Reading notes

- Before recording an instructional video, the author practices the code to work out variable names, syntax, the editor to use, and whether it works.
- The choice of setup depends on the code and the best way to show the behavior, using tools like the Node.js REPL, VS Code, the browser, CodeSandbox, or CodePen.
- Before recording, the author prepares the windows, enlarges the editor if possible, turns off notifications, and removes extra browser visuals.
- Screenflow is set to record the screen only, without audio, and the author leaves buffer at the end of the recording.
- The author says the recording usually takes one or two takes, and more if the practice step was skipped.
- In editing, the author often resizes the screen to focus on the important information, using Screenflow's resize function.
- Sometimes the font size is adjusted in post with the Scale function, especially when recording a browser inspector window.
- Annotations can be added as colored boxes, arrows, or text to cover something that could not be cropped or to add a small character.
- Narration is added after the video is already solid, using Insert > Narration, with the Shure microphone selected as input.
- When the spoken pace is slower than the typing pace, freeze frame can extend a section of the recording so the narration can fit.
- The author says this method made it possible to finish the video part of a course in about a day, then return later to add narration.
