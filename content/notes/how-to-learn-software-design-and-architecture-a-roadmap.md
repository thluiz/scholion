The article presents a roadmap for learning software design and architecture as a sequence of stages. It starts with clean code, then moves through programming paradigms, object-oriented programming, design principles, design patterns, architectural principles, architectural styles, architectural patterns, and enterprise patterns. 

## Reading notes

- Clean code is the first step toward long-lasting software, because code that is easy to understand and change helps keep a project stable over time.
- The article recommends learning the three major programming paradigms and understanding where each one fits in software design.
- Object-oriented programming is presented as the clearest tool for architecture because it supports plugin architectures and rich domain models.
- Design principles are described as established object-oriented best practices, including composition over inheritance, encapsulating what varies, programming to abstractions, SOLID, DRY, and YAGNI.
- Design patterns are grouped into creational, structural, and behavioural categories, and the article warns that they add complexity if used without need.
- Architectural principles are framed as guidance for organizing components, separating policy from detail, and identifying boundaries and subdomains.
- Architectural styles are presented as high-level patterns, including component-based, monolithic, layered, event-driven, publish-subscribe, client-server, and peer-to-peer systems.
- Architectural patterns are described as more tactical implementations of styles, with examples such as Domain-Driven Design, MVC, and event sourcing.
- Enterprise patterns are introduced as ways to handle concerns that MVC leaves unclear, including entities, value objects, and domain events.
- The article closes by linking scale, audits, and performance to message queues, caches, Event Storming, DDD, CQRS, and Event Sourcing.
