The page presents Git as the third skill in the Learn Enough developer-fundamentals series and explains why version control matters for software work. It frames Git as the tool covered here because it is widely adopted, practical, and central to both solo development and collaboration.

## Reading notes

- The tutorial is the final installment in a trilogy covering Unix command line, text editors, and version control.
- It says Git does not assume prior familiarity with version control.
- It argues that version control lets you track file history, try speculative changes, back up projects, collaborate, and deploy websites more easily.
- It links Git usage to the Learn Enough idea of "technical sophistication".
- It recommends using Unix, preferably on Macintosh OS X or Linux, and gives setup steps for Git and Bash prompt completion.
- It shows how to initialize a repository, create a first file, stage changes, commit them, inspect history, and read diffs.
- It explains commit messages, amended commits, and the use of SHAs to refer to earlier states.
- It adds HTML structure to a simple site and uses that example to show iterative commits.
- It covers adding a README, pushing to GitHub, and using Markdown for the rendered README.
- It introduces .gitignore for files such as .DS_Store and temporary editor files.
- It explains branching, merging, checking out branches, and recovering from mistakes with force checkout or by using commit SHAs.
- It describes cloning a repository, pulling changes, pushing updates, and handling both non-conflicting and conflicting merges.
- It shows how to push a branch for GitHub Pages so a static site becomes publicly available online.
- It ends by encouraging further learning and presents the tutorial as enough to begin using Git confidently.
