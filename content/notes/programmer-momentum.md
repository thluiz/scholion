The text argues that coding progress depends on momentum. Before starting, a programmer has to load language details, project goals, business logic, database queries, and code-specific context into working memory. The best momentum comes from planning the next steps in comments so the work queue stays visible and ready.

## Reading notes

- Coding starts slowly because the programmer has to reload a lot of context into memory.
- The mental load includes language syntax, project purpose, technical debt, application impact, business value, reuse, and customer experience.
- Momentum grows when the next steps are written ahead of time in comment form.
- A prepared step list helps work move faster, more efficiently, and more effectively.
- Momentum breaks when something does not work as expected, when someone interrupts, or when time runs out.
- Debugging skill and experience reduce the damage from unexpected problems.
- Interruptions such as email, meetings, and coworkers cause large losses because the context has to be loaded again.
- The suggested response to interruptions is to ask whether the task is urgent and defer it when possible.
- Long uninterrupted work sessions can feel efficient, but the text says to stop when mistakes start or a problem becomes unclear.
