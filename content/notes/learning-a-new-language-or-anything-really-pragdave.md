The author recommends learning a new language by picking a real but nonvital task, one that fits in a few hundred lines of code. The point is to use the language on something useful, not to finish polished code on the first pass.

## Reading notes

- Choose a task you want to do and that would be useful rather than vital.
- Pick one aspect of that task and prototype it in the new language.
- Expect to spend time learning the tooling and looking things up.
- Treat mistakes and awkward code as part of the learning process.
- After about a week, throw the first version away and rebuild it.
- The second attempt should be faster and feel like better code.
- Keep digging into the language and tooling once you start feeling productive.
- Hitting a wall is normal and comes after enough familiarity that you start judging design choices instead of basic feasibility.
