The post argues that top developers are made by discipline and by building things, not by theory alone. It presents seven project ideas as ways to practice different skills, repeat them in different stacks, and learn through mistakes.

## Reading notes

- The author says experience teaching more than 1000 students and seeing them in industry led to the conclusion that becoming a top developer is a matter of discipline.
- Building and making mistakes are presented as part of learning because they help develop problem-solving skills that theory alone does not teach.
- The seven project ideas are meant to be recreated with any technology stack the reader wants to learn.
- Project 1 is a to-do app, framed as a beginner-level “Hello World” for application development, with tasks, validation, and filtering as the main skills.
- Project 2 is a products admin dashboard, used to practice CRUD, database interaction, input validation, and form handling.
- Project 3 is a card memory game, aimed at DOM manipulation, UI events, animations, and basic logic in views.
- Project 4 is paint software, focused on canvas work, low-level screen manipulation, UI events, and design patterns such as command, singleton, and strategy.
- Project 5 is a bot, with examples ranging from simple greeting bots to bots that post quotes, respond to follows, react to topics, and learn from user behavior.
- Project 6 is a messenger clone, meant to show how native or hybrid apps and web apps work, including websockets, layouts, and routing.
- Project 7 is a chess engine or chess game, presented as a harder project for understanding native apps, web apps, and real-time gameplay.
- The conclusion says personal projects improve skills, make it easier to move between stacks, and should be shared so other developers can use them as inspiration.
