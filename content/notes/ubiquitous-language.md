Eric Evans uses “Ubiquitous Language” in Domain Driven Design to name the practice of building a common, rigorous language between developers and users. The language is based on the software’s domain model, so it needs precision because software handles ambiguity poorly.

He says using that language with domain experts helps test both the language and the model. He also says the language and the model should change as the team learns more about the domain.

## Reading notes

- a shared language should be precise and grounded in the domain model
- conversations with domain experts help test the language and the model
- the language and the model should evolve as understanding of the domain grows
- domain experts should challenge awkward or inadequate terms and structures
- developers should watch for ambiguity or inconsistency that could hurt design
