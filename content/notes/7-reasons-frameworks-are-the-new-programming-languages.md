Frameworks have become the main site of programming debates because syntax differences across languages matter less than they used to. Automation, cross-compilers, IDEs, and visual tools reduce the importance of language details, while APIs, libraries, and framework architecture shape how developers actually work.

## Reading notes

- Most coding now consists of chaining API calls rather than exploiting language features in depth.
- Understanding how APIs behave, what data they accept, and how their algorithms scale matters more than syntax.
- Frameworks let developers build on existing code bases instead of rewriting everything in a new language.
- Learning the architecture and libraries behind a framework is more useful than mastering the syntax of the language it sits on.
- Many important programming problems are now about algorithms and data structures implemented by frameworks.
- Compilers and smart IDEs reduce the need to manage punctuation and other syntax details.
- Visual tools make some code less dependent on textual language rules.
- Frameworks set the rules and limits of what can be done, which is why they carry more power than the language alone.
