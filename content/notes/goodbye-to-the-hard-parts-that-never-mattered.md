The piece argues that much of software engineering used to involve toil that was only loosely tied to the real problem. Coding agents can now take over more of that translation work, but the engineer still has to understand the system, judge outputs, test changes, and take responsibility for what ships.

It also says the shift can expand learning and creative range, because agents make it easier to explore unfamiliar languages, systems, and projects. The author still flags real risks, including bad code at scale, pressure on jobs, changes to junior training, and unequal access to tools.

## Reading notes

- A lot of the old difficulty in software work was labor around the problem, not the problem itself.
- Coding agents can generate parsers, navigate codebases, and recall library calls faster than a person.
- Agents still make wrong assumptions, miss local conventions, and fail to test their changes.
- Engineering still requires understanding the system, choosing where a change belongs, reproducing failures, and standing behind the result.
- The author says the work has moved from typing and scaffolding toward direction, judgment, verification, and responsibility.
- Using agents can tighten the learning loop by making it easier to explore Rust, Linux, infrastructure, database behavior, and terminal tools.
- The risk is that people may accept generated code without learning, which can make them worse engineers.
- The article also warns that companies may cut staff, generated code may scale failures, junior career paths may change, and access to expensive tools matters.
- Faster code generation makes discipline more important, not less, because bad assumptions can spread quickly.
- The author rejects the idea that software engineering is dead and treats the change as a new way of working.
