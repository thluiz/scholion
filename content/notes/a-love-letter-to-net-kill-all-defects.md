The author says .NET has changed a lot since 2001 and now fits a world shaped by cross-platform deployment and cloud services. He values Microsoft’s shift toward open-source tools, Docker, AWS support, and front-end options like TypeScript and Blazor.

## Reading notes

- .NET began as a managed framework meant to replace DLL hell and improve COM interoperability.
- It let developers use VB.NET, C#, and later F# on the same platform.
- The platform moved from Windows desktop and web work toward cross-platform and cloud development.
- Microsoft accepts that servers now run in Docker and on non-Windows platforms.
- The company also supports cloud environments beyond Azure.
- The Microsoft stack has gone through many front-end approaches, including Windows Forms, WPF, Silverlight, ASP.NET WebForms, MVC, and Blazor.
- JavaScript became a central part of the stack, and TypeScript helped add compile-time type safety.
- VS Code is presented as a free cross-platform IDE that works well for JavaScript development.
- Visual Studio now runs on Mac.
- Blazor is described as an emerging way to use compiled languages to build web apps through WebAssembly.
- The author prefers .NET for back-end code and for desktop and mobile development.
- He prefers Angular and JavaScript or TypeScript SPAs for the front end, with a .NET back-end API.
- C# is praised for object-oriented programming.
- .NET provides built-in libraries and many NuGet packages.
- F# is presented as a functional option that can interoperate with C# and VB.NET.
- The author values generics, extension methods, lambda expressions, LINQ, and EntityFramework.
- .NET Core web apps are described as having little boilerplate and easy middleware integration.
- The platform is compared to the Borg because it keeps adding new capabilities as needs change.
- The author recommends starting with a console app or a .NET Core Web API.
- He describes the .NET community as professional, courteous, and innovative.
