O texto defende que boas práticas são as que maximizam a eficácia. Isso ocorre quando ajudam a entregar o valor certo para o cliente com o menor custo para a empresa, seja melhorando a entrega do que o cliente espera, seja reduzindo o custo total de propriedade.

Também afirma que o contexto do projeto importa. Em software com manutenção futura, práticas que facilitam compreensão, modificação, teste e distribuição aumentam a eficácia. Em projetos sem manutenção prevista, investir em manutenibilidade pode só elevar o custo. O texto sustenta ainda que antecipar necessidades futuras costuma aumentar complexidade e desperdiçar dinheiro, e que priorizar o que é mais importante pode acelerar o retorno para o cliente.

## Fichamento

- Boas práticas são as que garantem a entrega do valor certo para o cliente com o menor custo para a empresa.
- Toda feature que o cliente não percebe vira apenas custo de desenvolvimento.
- O valor correto não pode ficar abaixo de um software que faz o que se propõe sem erros nem inconsistências.
- Software deve ser projetado para reduzir o custo total de propriedade, incluindo desenvolvimento e manutenção.
- Tentar prever necessidades futuras pode aumentar a complexidade das mudanças que não foram planejadas.
- Antecipar investimento tende a desperdiçar dinheiro, porque o dinheiro disponível hoje vale mais que o de amanhã.
- Em projetos com manutenção futura certa, reduzir custos de compreensão, modificação, teste e distribuição aumenta a eficácia.
- Desenvolvedores têm pouca ou nenhuma condição de aumentar o valor correto para o cliente; isso depende de necessidade de negócio.
- O foco do desenvolvimento deve ser entregar pouco mais do que o cliente espera.
- Se possível, o mais importante deve ser entregue antes.
- Uma prática só é boa quando é avaliada no contexto do projeto em que será aplicada.
- Em alguns projetos, melhorar a manutenibilidade não é boa prática porque só aumenta o custo.
- Otimização prematura é apresentada como raiz de todo mal.
