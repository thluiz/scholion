The post argues that using VSCode without a mouse is about speed and reducing friction in the parts of the workflow used most often. It recommends starting with the default shortcuts, then focusing on the navigation actions that matter most in daily work.

## Reading notes

- The main goal is to optimize the hottest path in the daily workflow instead of memorizing many shortcuts.
- File Explorer can be opened with `CMD+SHIFT+E`, project search with `CMD+SHIFT+F`, and Source Control with `CTRL+SHIFT+G`.
- In File Explorer, `ENTER` renames a file, while `CMD+Down_Arrow` opens it.
- In project search, `CMD+Down_Arrow` moves to the results so files can be navigated without the mouse.
- `CMD+0` focuses the left panel, `CMD+1` focuses the first open editor, and `CMD+2` can focus the second split editor.
- The terminal can be shown with `CMD+J` or ``CTRL+` ``.
- The post shows a custom keybinding in JSON so one key can switch focus between the terminal and the editor.
- Inside a file, `CMD+Up_Arrow` and `CMD+Down_Arrow` jump to the top or bottom.
- `CMD+SHIFT+O` opens symbol navigation within the file.
- `CMD+F` can be used to jump quickly to a section by searching for text in the file.
- The closing advice is to start small and improve the shortcuts used most often.
