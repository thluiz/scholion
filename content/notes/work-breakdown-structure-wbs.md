A work breakdown structure organizes project work as a deliverable-oriented hierarchy. It starts with the project at the top level and decomposes it into sub-deliverables and work packages until specific tasks can be assigned, estimated, and tracked.

The page says WBS helps define scope, allocate time and cost, support budgeting and scheduling, identify risks, and monitor progress. It also notes that work packages should be independent, unique, and kept under 10 days when possible.

## Reading notes

- A WBS is a key project deliverable that organizes work into manageable sections.
- PMBOK defines it as a deliverable-oriented hierarchical decomposition of the work to be executed by the project team.
- Each level adds more definition and detail to the project scope.
- The structure begins with the project as the top-level deliverable and breaks it into sub-deliverables.
- Sub-deliverables are decomposed until a single person can be assigned.
- Work packages contain the tasks needed to produce a specific unit of work.
- Work packages can be grouped with cost accounts so the organization can track financial progress alongside project performance.
- Budgets, schedules, and time estimates can be developed from sections of the WBS.
- WBS branches that are not well defined indicate scope definition risk.
- A WBS can help identify communication points when integrated with an organizational breakdown structure.
- When a project falls behind, the WBS helps identify the deliverables affected by late or failing work packages.
- The page recommends top-level deliverables, assigned work packages, uneven levels of detail, work packages under 10 days, independence between work packages, and no duplication.
- It presents brainstorming, whiteboards, note cards, and sticky notes as ways to build a WBS.
- It highlights MatchWare MindView as a tool for mind mapping, WBS creation, Gantt charts, and exports to Microsoft Project and other tools.
