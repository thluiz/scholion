Barbara Liskov treats programming as a problem of design and mathematical reasoning. She says software should be organized into modules, with data abstraction used to control complexity and make programs easier to understand.

## Reading notes

- Good code should be substantive, concise, and readable by humans, without extraneous details.
- By the late 1960s, many programs were hard to read and unpredictable because they relied on long algorithms with goto statements.
- Liskov wanted to approach programming as a mathematical problem guided by logical principles and aesthetic beauty.
- At MIT, she led the team that created CLU, the first programming language that did not rely on goto statements.
- CLU used data abstraction to organize code into modules, and the article says Java, C++, and C# descend from it.
- Liskov received the 2008 Turing Award for work on programming language and system design, especially data abstraction, fault tolerance, and distributed computing.
- She says AI is an application rather than a core discipline, and that machine learning can work well but does not always explain why it works.
- She compares software design to proving a theorem, where the problem is decomposed into lemmas or subproblems until it can be implemented on a real machine.
