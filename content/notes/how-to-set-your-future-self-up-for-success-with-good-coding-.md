The article says developers should think about their future selves when they write code. It groups several habits that reduce confusion later, from making code easier to read to leaving enough context for others to work with it.

## Reading notes

- Use readable code instead of clever shortcuts when those shortcuts make later changes harder to understand or debug.
- Keep code style consistent across a team so the codebase feels like one person wrote it.
- Use linting and formatting tools such as ESLint and Prettier to catch and fix style differences.
- Add comments to explain complex logic and help the next person understand what the code is doing before changing it.
- Write documentation to describe the overall solution, business rules, architecture, or algorithm at a higher level than inline comments.
- Make pull requests give context by explaining what changed, what it affects, and how to reproduce or test the change.
- Use tests to confirm code keeps working the same way and to catch breakage before it reaches users.
- Start these habits early, but it is also worthwhile to adopt them later in a career because they make teamwork and maintenance easier.
